# Project documentation rules

## Scope

Write all project documentation in Simplified Technical English.
Apply these rules to new documentation and changes to existing documentation.
Include README files, guides, package descriptions, release notes, and explanatory comments.
Keep the legal text in `LICENSE` unchanged.

## Writing rules

- Use the writing principles of ASD-STE100 Issue 9.
- Use active voice for instructions.
- Use one instruction per sentence.
- Use no more than 20 words in an instruction sentence.
- Use no more than 25 words in a descriptive sentence.
- Use one topic per paragraph.
- Use no more than six sentences per paragraph.
- Use numbered lists for procedures with three or more steps.
- Use lists for three or more conditions.
- Use simple verb forms where they preserve the meaning.
- Do not use semicolons in prose.
- Do not use phrasal verbs.
- Do not use noun clusters with more than three words.
- Use a direct verb instead of a noun that describes an action.
- Use complete sentences in prose.
- Use short labels for headings and diagrams.
- Use one term for each concept.
- Use plain words without promotional claims.
- Define necessary technical terms in the glossary in `README.md`.

## Preserve technical meaning

- Keep commands, code examples, identifiers, paths, URLs, and configuration keys unchanged during a language rewrite.
- Keep numbers, units, defaults, conditions, exceptions, and version requirements unchanged during a language rewrite.
- Preserve uncertainty in the source text.
- Do not change a possible result into a certain result.
- Do not add technical claims without evidence.
- If a writing rule would remove necessary precision, preserve the precision.
- Explain any necessary exception to a writing rule.
- Change technical content only when the task requires that change.

## Check documentation changes

1. Read the source text before you rewrite it.
2. Check that the new text preserves all technical facts and conditions.
3. Check the sentence lengths and paragraph lengths.
4. Check terminology against the glossary in `README.md`.
5. Check that links and code examples remain correct.
6. Check the rules for each changed document before you complete the task.

## Compliance limits

These rules do not include the official ASD dictionary.
Do not claim certified or dictionary-checked ASD-STE100 compliance without a separate check against the official standard.
Use the [official ASD website](https://www.asd-ste100.org/STE_downloads.html) to request the standard when a task requires that check.
